# Отчёт — C++17 SAST/SCA, цель 7/10, Ubuntu Linux

## 0. Сведения о работе

- **Приложение:** Security Archiver — консольное сжатие файлов и stdin в формат zlib.
- **ОС выполнения лаборатории:** Ubuntu Linux (Intel или Apple Silicon); команды и конфигурация в README.
- **Язык:** C++17, CMake.
- **LLM:** ChatGPT, GPT-6. Запрос пользователя: «Создай учебное консольное приложение на C++17 под Ubuntu Linux для демонстрации анализа безопасности с помощью SAST и SCA. Ввод из файла или stdin; минимум две ошибки разных типов, включая ошибку памяти; одна сторонняя зависимость фиксированной версии с известной CVE; сборка и основная функция должны работать».
- **Целевой уровень:** 7/10 = три **разных** SAST + сравнение + один SCA.
- **Важно:** ниже структурированы **подтверждённые исходным кодом** намеренные дефекты и **проверенная по NVD** CVE. Статусы конкретных инструментов надо взять из сырых отчётов после запуска на Mac. Сборка и базовая работа кода проверены отдельно на Linux с системной zlib; это не подменяет сборку с закреплёнными версиями.

## 1. Программа и версии зависимости

| Сборка | Исходники | Обрабатывает stdin/файл | zlib при обычной сборке | Режим |
|---|---|---|---|---|
| Исходная | `src_vulnerable/main.cpp` + `src_common/` | да | 1.2.11 (фиксированный SHA-256) | намеренно уязвима |
| Исправленная | `src_fixed/main.cpp` + `src_common/` | да | 1.3.2 (фиксированный SHA-256) | исправлена |

Фиксированные SHA-256 находятся в `CMakeLists.txt`. Вызов `compress2(..., Z_BEST_COMPRESSION)` в `src_common/archiver.cpp` реально использует библиотеку. Именно функция сжатия делает CVE-2018-25032 применимой по затронутому компоненту; конкретная эксплуатация зависит от специальной структуры данных и **не доказана обычным текстовым тестом**.

**SBOM:** `security/sbom-vulnerable.cdx.json` и `security/sbom-fixed.cdx.json` содержат direct dependency, PURL, CPE, версию и checksum архива. SBOM составлен **по CMake-манифесту** (`scripts/make_sbom.py`), не получен автоматическим анализом готового бинарника. Поскольку ссылка статическая, сканировать лишь текущий Homebrew/Python environment бессмысленно для определения этой версии.

## 2. Настоящие намеренные ошибки и привязка к строкам

### V1 — CWE-120: Buffer Overflow

- **Где:** `src_vulnerable/main.cpp`, вызов `std::strcpy(label, argv[++i])` внутри ветки `--label`.
- **Причина:** `char label[32]` — фиксированный буфер стека, а строка из командной строки не ограничена. Длина 32 и более байт вместе с завершающим `\0` может выйти за границы; также более длинный ввод гарантированно превосходит ёмкость. Конкретные последствия — UB, возможный сбой или повреждение памяти.
- **Как проверить безопаснее:** сначала SAST; демонстрацию ошибки памяти проводить при необходимости в отдельной ASan-сборке, не использовать реальные документы или важные файлы.
- **Исправление:** `src_fixed/main.cpp`, `std::string label`, без `strcpy` и фиксированного буфера.
- **OWASP аналог:** [Buffer Overflow](https://owasp.org/www-community/vulnerabilities/Buffer_Overflow) или [описание OWASP](https://community.owasp.org/vulnerabilities/Buffer_Overflow) — переполнение при записи в недостаточный буфер.
- **БДУ (аналог по CWE, не наш проект):** [BDU:2025-11706](https://bdu.fstec.ru/vul/2025-11706) — в записи бюллетеня НКЦКИ указан **CWE-120** (реальная уязвимость Cisco, *не* CVE нашего кода); [подтверждающий бюллетень](https://safe-surf.ru/upload/VULN-new/VULN.2025-09-29.1.pdf). Связь — одинаковый **тип** ошибки, не общая реализация.

### V2 — CWE-22: Path Traversal

- **Где:** `src_vulnerable/main.cpp`, `fs::path("output") / output_file` после получения `--output` без валидации.
- **Причина:** путь `../escaped.zlib` покидает предполагаемый каталог `output`, потому что значение является частью пути. Есть риск перезаписать доступные процессу файлы.
- **Безопасная демонстрация:** `tests/test_behavior.py` проверяет `../escaped.zlib` только в **одноразовом временном каталоге**. В уязвимой версии файл появляется вне `output/`, в исправленной запись отклоняется.
- **Исправление:** `src_fixed/main.cpp`: принимает лишь basename без `.` / `..` и разделителей пути, открывает каталог через `O_DIRECTORY|O_NOFOLLOW`, файл через `openat(..., O_NOFOLLOW)` — запрещено использование симлинка в пути записи.
- **OWASP аналог:** [Path Traversal](https://owasp.org/www-community/attacks/Path_Traversal) или [описание OWASP](https://community.owasp.org/attacks/Path_Traversal) — выход из разрешённого каталога.
- **БДУ (аналог по CWE, не наш проект):** [BDU:2024-08843](https://bdu.fstec.ru/vul/2024-08843), CWE-22 (продукт Mitel MiCollab; [бюллетень НКЦКИ](https://www.cert.gov.ru/upload/iblock/833/ykzayze5uz11ru7wpjx5ccnb6ibffwww/VULN.2025_01_10.1.pdf)). Связь — одинаковая категория ошибок проверки пути, но чужой продукт и иной вектор атаки.

### V3 — CVE-2018-25032: уязвимая зависимость zlib 1.2.11

- **Где:** `CMakeLists.txt` в ветке `LAB_FIXED=OFF`, + `src_common/archiver.cpp` вызывает `compress2`.
- **Причина:** версия upstream zlib **до 1.2.12** затронута повреждением памяти во время deflate при специфических входных данных (ошибка **CWE-787** — out-of-bounds write).
- **NVD:** [CVE-2018-25032](https://nvd.nist.gov/vuln/detail/CVE-2018-25032) — базовая оценка NVD CVSS 3.1 **7.5 HIGH**. Системные пакеты с обратными патчами нельзя приравнивать к чистому upstream; у нас загружается именно upstream 1.2.11.
- **OWASP аналог:** [Buffer Overflow](https://community.owasp.org/vulnerabilities/Buffer_Overflow) — выход за допустимые границы памяти, сходный класс; идентификатор самой CVE относится к **CWE-787**, а не автоматически к CWE-120.
- **БДУ (та же CVE):** [BDU:2022-01641](https://bdu.fstec.ru/vul/2022-01641) — **точное соответствие** CVE-2018-25032, дополнительно подтверждено [бюллетенем РЕД ОС](https://redos.red-soft.ru/support/secure/uyazvimosti/uyazvimost-zlib-cve-2018-25032/).
- **Исправление:** во второй сборке используется upstream **zlib 1.3.2**. Конкретно CVE-2018-25032 по диапазону NVD к этой версии не относится. Это не гарантия отсутствия других CVE.

## 3. SAST — три независимых инструмента, их результаты и сравнение

| Анализатор | Тип | Конфигурация | Что реально следует считать находкой |
|---|---|---|---|
| **Semgrep** | SAST | `security/semgrep.yml`, собственные учебные правила | Совпадение `strcpy` или известной последовательности формирования небезопасного пути; правила целевые, не всеобщий анализ потоков данных |
| **Cppcheck** | SAST | `--enable=all --inconclusive --std=c++17` | Предупреждения по конкретным строкам / функциям, могут не распознать некоторые логические ошибки |
| **Flawfinder** | SAST | `--dataonly --minlevel=1` | Эвристические срабатывания на опасные C/C++ API (возможны FP) |

Скрипт `scripts/run_sast.sh` создаёт оригинальные отчёты для **обеих** версий, сохраняет команды в скрипте и версии в `reports/sast_environment.txt`. `scripts/compare_sast.py` читает результаты и создаёт `reports/COMPARISON.md`. Нельзя заранее утверждать, что каждое SAST-средство распознает каждую ошибку: Path Traversal как логический дефект часто пропускается лексическими анализаторами; явный `strcpy` может быть найден как риск даже без доказательства выхода за границы.

**Правила интерпретации:**

- **TP** (true positive) — диагностика подтверждённой ошибки в конкретной строке и ветке программы.
- **FP** (false positive) — срабатывание, для которого разобран поток данных и ошибка не подтверждается (например, опасная функция вызвана на заранее проверенных данных); слово «FP» не означает просто «не написано в задании».
- **FN** (false negative) — известная намеренная ошибка V1/V2, которую инструмент **не** отметил в своём отчёте.

**После реального запуска на Ubuntu Linux** вставьте сюда цифры из `reports/COMPARISON.md` и 2–3 строки доказательств из сырых JSON/XML/TXT:

| Анализатор | Исходная: V1 (CWE-120) | Исходная: V2 (CWE-22) | Исправленная: V1/V2 | Ссылки на файлы отчётов |
|---|---|---|---|---|
| Semgrep | заполнить (TP/FN) | заполнить (TP/FN) | заполнить по JSON | `reports/semgrep_*.json` |
| Cppcheck | заполнить | заполнить | заполнить | `reports/cppcheck_*.xml` |
| Flawfinder | заполнить | заполнить | заполнить | `reports/flawfinder_*.txt` |

**Пропущенные намеренные ошибки**: для каждого анализатора перечислите V1/V2, если по их строкам нет диагностики в оригинальном отчёте. Для других замечаний инструментов проведите ручную верификацию, не называя их ошибками без проверки.

## 4. SCA — SBOM, CVE, повторный анализ

**Инструмент:** Grype. **Зависимости:** zlib upstream, статическая линковка; в CycloneDX явно указаны версия, CPE и `purl` в формате `pkg:generic/zlib@...`. Grype использует NVD/CPE matching и может давать как FP, так и FN, поэтому сверяем данные с NVD.

Команды:

```bash
bash scripts/run_sca.sh
# внутри скрипта выполняется:
grype sbom:security/sbom-vulnerable.cdx.json -o json
grype sbom:security/sbom-fixed.cdx.json -o json
```

Сведения об SCA должны быть взяты **после реального запуска**, не из предсказания:

| Версия | Подтверждённая зависимость | Применимость CVE-2018-25032 по NVD | Обнаружено инструментом |
|---|---|---|---|
| Исходная | zlib upstream 1.2.11 | Да — работает путь `compress2` | Взять из `reports/grype_vulnerable.json` |
| Исправленная | zlib upstream 1.3.2 | Нет — вне уязвимого диапазона | Взять из `reports/grype_fixed.json` |

Проверьте вывод `reports/SCA_COMPARISON.md`. Если Grype ничего не нашёл, не выдумывать CVE в отчёте: объяснить FN/неполную поддержку generic/CPE и подтвердить **применимость** по NVD. Повторная сборка и тесты под новую версию в `tests/test_behavior.py`.

## 5. Исправления и повторный анализ

| Было | Стало | Что проверяет тест / анализ |
|---|---|---|
| `char label[32]` + `std::strcpy` | `std::string label` | Корректный длинный label в fixed; повторный SAST, исходная строка `strcpy` исчезла |
| `"output" / output_file` без проверки | Строгий basename + безопасный `openat`, `O_NOFOLLOW` | Попытка `../escaped.zlib` успешна только в исходной сборке; fixed отклоняет path traversal и симлинк |
| zlib 1.2.11 с известной CVE | zlib 1.3.2 | Сборка и распаковка результата, повторное Grype-сканирование нового SBOM |

**Состояние выполнения на момент создания архива:** исходники обеих версий проверены здесь на Linux с системной zlib; результаты SAST/SCA и сборка под Mac **не получены** (сеть и инструменты в среде подготовки отсутствуют). Это готовая воспроизводимая методика, но не поддельные готовые результаты сканеров.

## 6. Команды и окружение для сдачи

```bash
bash scripts/run_all_ubuntu.sh
# если запускаете вручную:
cmake -S . -B build-vulnerable -DLAB_FIXED=OFF -DCMAKE_BUILD_TYPE=Debug
cmake --build build-vulnerable --parallel 4
cmake -S . -B build-fixed -DLAB_FIXED=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-fixed --parallel 4
python3 tests/test_behavior.py ./build-vulnerable/security_archiver ./build-fixed/security_archiver
bash scripts/run_sast.sh
bash scripts/run_sca.sh
```

Выводы инструментов находятся в `reports/`. Версии — в `reports/sast_environment.txt`, `reports/sca_environment.txt`. Для воспроизводимости укажите дату и версию базы Grype. Снимки экрана уместны как дополнение, но **не заменяют** оригинальные отчёты.
